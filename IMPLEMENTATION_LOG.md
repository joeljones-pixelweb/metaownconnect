## Phase 4 — Model layer files

Created under `lib/features/wallet/models/`:

- `connected_wallet.dart` — `ConnectedWallet` (address, CAIP-2 chainId, wallet name, connectedAt), EVM address validation regex, `shortAddress` display abbreviation, chain-id helpers, value equality on (lowercased address, chainId).
- `blockchain_network.dart` — `BlockchainNetwork` (chainId, name, nativeSymbol, nativeDecimals, rpcUrl, fallbackRpcUrl, explorerUrl, isTestnet, HTTPS check) and `BlockchainNetworkRegistry` with Sepolia (dev default), Ethereum mainnet, Polygon, Base, Arbitrum One; `byChainId`/`byNumericChainId` normalise to CAIP-2 and return `null` for unknown chains.
- `native_balance.dart` — `NativeBalance` (BigInt `wei`, fetchedAt, `BalanceSource` rpc|cached) and integer-only `BalanceFormatter` (hex→BigInt parse, round-half-up formatting, thousands grouping).
- `wallet_failure.dart` — sealed `WalletFailure` hierarchy with 13 typed failures (user-safe message + `canRetry`).
- `wallet_view_state.dart` — `WalletStatus`, `BalanceStatus`, and the immutable `WalletViewState` aggregate (status, wallet, balance, balanceStatus, connectionFailure, balanceFailure, notice, lastBalanceUpdate, derived getters, `copyWith` with sentinel-based null overwrite).

## Phase 5 — Data / service layer files

Created under `lib/features/wallet/services/`:

- `wallet_connection_service.dart` — `IWalletConnectionService` + `WalletConnectionService`: idempotent init of `ReownAppKitModal` with `PairingMetadata`/`Redirect` from `AppConfig`, `kMetaMaskWalletId` featured wallet, MetaMask resolution via `GetIt.I<IExplorerService>` (8 s poll, name-or-id match), `selectWallet` + `connectSelectedWallet`, fallback to `ReownAppKitModalAllWalletsPage`, event subscriptions (connect/update/network-change/disconnect/error/expire/update), `mapModalError`, session→`ConnectedWallet` conversion, full teardown in `dispose()`. SDK types never escape the class.
- `wallet_service_events.dart` — sealed `WalletServiceEvent` union: `WalletSessionConnected`, `WalletSessionUpdated`, `WalletSessionDisconnected`, `WalletSessionExpired`, `WalletConnectionFailed`.

Created under `lib/features/wallet/data/`:

- `blockchain_balance_service.dart` — `IBlockchainBalanceService` + `BlockchainBalanceService`: HTTPS-only endpoint selection with primary→fallback retry, `rpc.walletconnect.org` parameterisation (`chainId` + `projectId`), `eth_getBalance` POST with 20 s timeout, typed failure mapping, wei parsing via `BalanceFormatter`.
- `wallet_repository.dart` — `WalletRepository` façade over the two service interfaces (initialize, connect, sheet, disconnect, peek session, fetch balance, event stream).

## Phase 6 — ViewModel + Riverpod providers

Created under `lib/features/wallet/viewmodels/`:

- `wallet_view_model.dart` — `WalletViewModel extends Notifier<WalletViewState>` + `walletViewModelProvider`: SDK bootstrap (`initialize`), connect/disconnect actions with duplicate-tap guard, 120 s approval timer, service-event handling, `_applySession` (clears balance on account/chain change), `_loadBalance` with monotonically increasing `_balanceRequestId` and `_isCurrentBalanceRequest` stale-response guard, typed-failure surfacing, `ref.onDispose` cleanup. `approvalTimeout` is a mutable field so tests can shorten it.

## Phase 9 — Tests (deferred)

- **Decision: automated test files were explicitly deferred for this iteration.** The stock `test/widget_test.dart` template (which referenced the removed `MyApp` class) was deleted, and the `test/` directory is intentionally empty.
- The design seams the future suite needs are already in place:
  - interface-typed dependencies `IWalletConnectionService` and `IBlockchainBalanceService`;
  - `WalletRepository` built from those two interfaces only;
  - standalone Riverpod providers (`walletConnectionServiceProvider`, `blockchainBalanceServiceProvider`) that `ProviderScope` overrides can replace with fakes;
  - injectable `http.Client` inside `BlockchainBalanceService`;
  - `mapModalError` marked `@visibleForTesting`;
  - stable widget keys (`connect_metamask_button`, `wallet_address`, `copy_address_button`, `refresh_balance_button`, `disconnect_button`, `balance_value`, …);
  - the configurable `WalletViewModel.approvalTimeout` for timeout scenarios.
- Planned suite (outstanding): fakes + provider overrides covering initial disconnected state, connect flow, real-address display, address formatting, copy-address, wei conversion, rejection → disconnected, failure messaging, network-change refresh, stale-balance guard, disconnect cleanup, unsupported chains, duplicate-tap guard.
- A device-level manual test plan (MetaMask Mobile on Sepolia, cold/warm start return flows) was defined but not executed in this environment.

## Known limitations / not in scope

- **No transactions and no signing** — v1 performs `eth_getBalance` reads only; no `eth_sendTransaction`, no message signing.
- **No SIWE / ownership verification** — a public address is display data only, never auth.
- **Link Mode disabled** — no universal links (associated domains + AASA) are configured, so `LINK_MODE` defaults to `false`; the return flow uses the native `metaownconnect://` scheme.
- **MetaMask logo is a placeholder** — `MetaMaskMark` is an orange rounded square with an "M", not the official MetaMask brand asset (licensing).
- **Direct MetaMask connect depends on the WalletConnect explorer listing** being reachable and containing MetaMask; on failure/timeout (8 s) the app falls back to the SDK's all-wallets sheet rather than failing.
- **Approval timeout is a fixed 120 s** (`WalletViewModel.approvalTimeout`); no exponential back-off or user-configurable window.
- **EVM chains only** — the registry and address validation are `eip155`-specific; non-EVM namespaces are rejected (`InvalidAccountFailure` on address lookup).
- **Balance reads are native-token only** — no ERC-20 `balanceOf`, no multi-token portfolio.
- **Network switching is not offered in-app** — the user switches networks in the wallet; the app reacts via `onModalNetworkChange`/session updates. Unsupported chains are shown but not auto-switched.
- **Session persistence across cold starts relies on the SDK** (`disconnectOnDispose: false` keeps sessions across rebuilds/hot restarts); full cold-start restore path exists (`initialize` applies `currentWallet()` when non-null) but has not been device-validated.
- **Automated tests are deferred** (Phase 9) and on-device manual test runs (MetaMask Mobile, Sepolia, cold/warm start) have not been performed. `flutter analyze` is clean, but this feature has **not** been claimed production-ready.
